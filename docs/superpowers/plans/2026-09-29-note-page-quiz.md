## 1. 目标口径：把「每篇都多道题」拆成两件事

用户原话含两层，必须分开承诺：

1. **功能层（可立即交付）**：每篇笔记都有「测一下」，有几题考几题，题题有正确答案 + 理由 + 来源。
2. **内容层（长期工程）**：每篇都凑够 ≥3 题。缺口 ＝ `83×3 + 278×2 + 185×1 = 990` 道净新增（零题篇补 3、单题篇补 2、双题篇补 1，三题及以上不动）。

把 (2) 当成 (1) 的前置会同时踩两个坑：**工期变成 330 轮无人值守**，以及为凑数灌水——AGENTS.md 与配方 §3 明写「凑数的低质内容不是产出，是负债」。故本案 (1) 先行、(2) 靠棘轮推进，卡片按真实题数呈现（1 题就写 1 题，不伪装成卷子）。

## 2. 六个关键决定（含被我自己否掉的路线）

### D1 卡片自建新岛屿，不改造 `/guide/quiz`

- **先试的路线（否）**：给 `Quiz.tsx` 加 `?note=<noteId>`，笔记页深链过去。三个硬伤：① 复用那条 `glob eager` 链路等于给每页挂 686 KB；② `Quiz.tsx` 的 `scope`/`round` 状态机是**方向语义**（`ascension-quiz-state-v1.scope.checked` 存方向 slug），塞进「单篇」维度会污染既有存档并触发轮次恢复异常——该组件第 227 轮刚修过一次首帧水合不匹配；③ 用户要「针对当前页面」，跳走再回来丢阅读上下文。
- **反向顾虑（承认并接受）**：新岛屿要重写判分逻辑，是重复实现。但该逻辑很小——`sameSet(picked, answer)` 一个比较 + 单选/判断即点即交、多选需「确认作答」，约 20 行；换来的是**既有作答页零回归面**。判定：重复成本 < 改造成本。
- **结论**：新建 `NoteQuiz`（Astro 服务端筛题 + React 轻组件作答）。

### D2 构建期按 `noteId` 过滤，不做运行期 fetch

在 `src/lib/` 加纯函数：读该方向 JSON → 过滤 `noteId === 本篇 id` → 返回题目数组，由 Astro 组件在构建期调用并作为 props 下传。

- **为什么不做运行期 fetch**：第 243 轮实测「题库构建期内联、`dist/` 下没有独立 JSON 产物」。改成 fetch 要为 571 页新增 33 份可寻址产物 + 一套 loading/失败态，收益只有「延迟加载」，而每页实际只需 1~4 题（≤3,159 B）。否。
- **为什么不用 `client:only="react"`**：会引入首屏空白并让题目文本不进索引；第 227 轮对同类权衡的结论一致。**代价要写明**：SSR 出 HTML 意味着答案可被 Ctrl+F 搜到。这是自测工具不是监考，与既有 `/guide/quiz` 同性质，**明示接受**，不做无意义的混淆。

### D3 「答案来源」＝正文逐字引文，小节名构建期反查

新增**一个**字段 `source`：该题依据的**笔记正文逐字引文**（≤60 字）。「出自哪一节」由构建期拿引文在正文里定位、反查最近的 `## ` 标题**推导**，不作为数据存储。

- **被否的三条路线**：① **存行号**——任何一次正文编辑都让它漂移，且没有闸门能廉价发现漂移，等于把假引用发给读者；② **只存小节名**——同节多题无法区分，读者仍要自己找那句；③ **存 URL 锚点**——正文没有逐段锚点。
- **选引文的决定性理由：它是可机械验真的凭据**。闸门能断言「`source` 逐字存在于 `noteId` 指向的笔记正文（剥 frontmatter／code fence／inline code 后）且**唯一命中**」，写错、写泛、写歪立刻判红。这与第 239 轮立的「按渲染文本判而不按源码形状猜」、以及题库第 4 项「`noteId` 写错只会静默 404，已由闸门卡住」是同一条工程哲学：**能验真的字段才是活字段**。副产品：「唯一命中」会自然逼出有信息量的引文，糊弄不过去。
- **形状**：`source?: string`，**先可选**。726 道存量题一次性补引文不是本计划范围，强行必填会把 M1 卡死。新增题**必须**带（写题脚本断言，沿用第 208 轮「含反引号或 `**` 即不落盘」的同种落点）；存量题在 C 车道触碰该篇时顺手回填。

### D4 题数不足时的呈现（成败关键）

- **≥1 题**：正常出题，标题「测一下（本篇 N 题）」，N 如实。
- **1 题（278 篇，最大一档）**：本篇题之后追加**同分类**（`<方向>/<等级>/<分类>/` 下其他篇）的题补足到 3，放进**视觉明确区分**的次级区并标注「本篇测验暂缺，先练本分类相邻知识点」——不与本篇题混同，不假装考的是本篇；补位题同样显示各自的来源。
- **0 题（83 篇）**：不渲染死控件。显示「本篇测验待补 · 本分类现有 M 题可练」并链到 `/guide/quiz` 对应方向。宁可诚实的空态，不给读者一个点开是空的按钮。
- **覆盖靠棘轮不靠运动**：给 `quiz-verify` 增一条**覆盖率读数**（零题篇数／core 零题篇数／带 `source` 题数占比），并按 `interview-verify` 第 9 项 `KNOWN_MISSING` 的既有形状做成「存量清单 + 空转守卫」——清单里的篇目本轮没补上判红、补上了不删项也判红。于是 C 车道每轮顺手销号，覆盖单调上升。

### D5 答完必须给全三件：正确答案 + 理由 + 来源

与既有作答页**有意分歧**的一处：`Quiz.tsx` 现在只在答错时渲染 `hint`（`:538-541`）；本篇小测**答对也渲染理由**——用户诉求原话是「必须有正确答案和答案来源、理由等」，答对不给理由等于少一半价值。每题呈现：我的选择 ↔ 正确项（逐项标态）、`hint` 理由、`source` 引文 + 「看正文这一句」锚链接（构建期把引文所在节标题 slug 算进去）。末尾汇总 `对 X / N`，并留一条链到 `/guide/quiz` 承接「想系统刷」的读者。

### D6 v1 不落本地存储

v1 只在组件内存答完状态，**不写** `ascension-quiz-state-v1`。

- **反驳（用户会问「那怎么追踪掌握度」）**：诉求原文是「看完不知道记不记得住，测一下就知道了」——当场反馈即已满足；写共享库会把「本篇小测」与「刷题轮次/错题本」两套语义焊死，并重新引入跨标签 `storage` 订阅与水合时序（第 227、233 轮在同一片踩过两次）。
- 持久化（成绩留存、答错自动进错题本、与状态圆点 `src/lib/learn.ts` 联动）列 **M4 待裁决**，不顺手做。

## 4. 验收标准（做到这些才叫 M1/M2 完成）

- **覆盖面**：`pnpm build` 后从 `dist/` 现数渲染出 `.note-quiz` 的页面集合，**必须等于 §0 复核命令得到的 571 篇笔记集**——不多（不得溢出到分类页与 `guide/*`，尤其 `tools/basic/cli/index`）不少（83 篇零题走空态还是完全不渲染，二选一并在实现说明里写死口径）。
- **题数一致**：抽 3 篇（≥3 题的 / 1 题的 / 0 题的）核对卡片标题题数 ＝ 数据现算值；补位区标注存在且与本篇区视觉可区分。
- **体积**：单篇岛屿 props 增量 **≤4 KB**（源码侧实测上界 3,159 B，留余量；中位应落在 ~0.6 KB）；`/guide/quiz` 的数据链路**不得因 M1 变大**（M1 不碰它）。**体积断言一律从源码侧确定性计算**——起草时想用 `dist/guide/quiz/index.html` 量岛屿字节，撞上并行 `astro build` 正在重建 `dist/`（同一条命令两次读到「存在／ENOENT」，不同正则还量出 672 KB 与 950 KB 两个数），**故共享 `dist/` 的瞬时读数不可作为证据**。
- **真机**（本机 Playwright + chromium 1440×900、亮暗双主题，`pnpm preview`；4321 若被并行会话占住则按 sha 核对后**只读复用、不 kill、不另起端口**）：① 单选点一下即判、多选点「确认作答」才判（**要真点，别信合成事件**）；② **答对时理由仍渲染**；③ `source` 引文可见且锚链接落在正确的 `## ` 小节；④ 补位区区分标注到位；⑤ 零题篇渲染空态、**无可点亮的死按钮**；⑥ 双主题对比度 ≥4.5:1（探针按祖先链自下而上以 alpha 合成，**不给透明色垫黑底**）；⑦ `pageerror` 两主题各 0；⑧ **与续读滚动恢复共存**：从正文中部进本页不出现位置跳动/闪烁；⑨ 窄屏无横向溢出（`scrollWidth` ＝ 视口宽）。
- **闸门**：`pnpm build` 通过；`pnpm verify:docs` **全绿且项数不变**（M2 后仍为当次现算项数，第 8 项只是文案变宽）；**注入反证**——把某题 `source` 改一个字 → 第 8 项必须判红，还原后读回全绿（照第 239 轮那次注入反证的形状；若用 `perl -i -pe` 注入要先 `git diff` 确认它真改到了文件，第 239 轮就险些因 perl 的 UTF-8 处理把「注入没生效」误判成「判定无效」）。
- **定界**：全程 `git status --porcelain` 里他人（含并行会话）改动一个字节不 stage、不 commit；只 `git add <自有路径>`。
