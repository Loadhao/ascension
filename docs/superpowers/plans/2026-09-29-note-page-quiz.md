**Goal:** 每篇笔记页有一个「测一下」入口，点开得到 **5–10 道只针对这一篇**的题，题型混合（选择题 / 判断题 / 面试题 / 考点），内容覆盖「本篇小节直考 + 本篇概念的发散追问 + 与相邻知识的相关性」，每题必须给出**正确答案、答案来源（正文逐字引文 + 所属小节）与理由**。分数与成绩记录不是目标。

**Architecture:** 数据侧新增与全局题库**分家**的「本篇卷」资产 `src/data/papers/<方向>.json`，一篇笔记一份卷，构建期由 `scripts/paper-verify.mjs` 逐题校验「小节真实存在 + 引文逐字命中」。展示侧在 `src/components/starlight/Footer.astro`（已有 `ProgressMark` 注入范式）挂 `<NotePaperIsland>`，收起态一行按钮、点击展开逐题作答；`section → slug` 由 `Astro.locals.starlightRoute.headings` 现取，不自己实现 slugger。**出题本身不发生在浏览器里**——站点是纯静态部署，见 §2。

**Tech Stack:** Astro 7 + Starlight 0.42、React 岛屿、Node 校验脚本（复用 `verify:docs` 现有闸门链，M1 落地后 **47 项**）。无新依赖、无服务端、不改 `astro.config.mjs` 部署形态。

## 2. 决定性约束：静态部署 ⇒「点击即出题」不能发生在点击时

事实 9 决定：浏览器里没有服务端可以调 LLM。因此「我点击就可以针对这个 synchronized 与锁升级来出题」只有两种落法：

- **A. 出题发生在构建之前**（写进仓库的数据，点击只是展开）；
- **B. 出题发生在点击那一刻**（必须新增后端 + 模型凭据 + 付费额度，并把部署形态从 GitHub Pages 静态改为带服务）。

本计划推荐 **A**，理由不是省事，而是**只有 A 能满足「必须有答案来源、理由」这条硬要求**：A 的引文可以在构建期逐字校验（§5），B 的引文无法保证存在于正文里——运行时生成的题最容易犯的错误恰恰是「题干合理、正文无据」，对教学站是负资产。**B 涉及付费与凭据，属 `docs/evolution-recipes.md` §5 停止条件，只能由用户裁决，我不擅自采用。**

## 3. 三条路线的取舍

### R1（推荐）· 离线预生成「本篇卷」并入库

由我（agent）逐篇读正文 → 按小节起草 5–10 题 → 落 `src/data/papers/<方向>.json` → 过闸门 → 提交。与站内既有内容的生产方式一致（AGENTS.md 只禁止 AI 生成**图像**与第三方**音视频**素材，文字内容本来就是这样写的）。

- 优点：静态部署不变；引文与锚点可**机器校验**；答后能给出「跳到那一节」的真链接；读者离线可用。
- 代价：371 篇核心卷 × ≈7 题 ≈ **2,597 题**，571 篇全量 ≈ **3,997 题**，是现有题库的 3.6–5.5 倍。按事实 10 的节奏（C 车道每日 ≈4.8 次），每轮出 1 套 → 核心层约 **77 天**、每轮 2 套 → 约 **39 天**；全量 119／59 天。**这是内容生成问题，不是代码问题**，一次性做不完，必须按 §7 分层推进。

### R2（待裁决，不推荐先做）· 运行时调模型出题

需要新增 adapter/后端、模型 API key 与费用预算，并解决「无引文可校验」。技术上可行但推翻静态前提，且触发停止条件 → 交给用户。

### R3（已证伪）· 复用全局题库按 `noteId` 装配

v1 走的这条路。两条独立证据否证：

1. **概念不符**：用户明确「他和题库还有是区别的」，题库是全集、测一下是当篇发散与相关性。
2. **数量不够**（事实 4/5，site-wide 实测）：

| 装配口径 | ≥5 题 | ≥8 题 | 全 0 题 | 中位 |
|---|---|---|---|---|
| 仅本篇直考 | **0 篇（0.0%）** | 0 | 83 | 1 |
| 本篇 + 同组邻接 | 124（21.7%） | 12（2.1%） | 41 | 3 |
| 本篇 + 全部邻接 | 230（40.3%） | 76（13.3%） | 21 | 4 |

即使采用最激进口径，也有 **59.7% 的笔记凑不满 5 题**，且「邻接题」不是「当篇检测」——它把读者刚读的正文换成了别的文章。邻接数据留作 R1 里 `relate` 题的**选题线索**，不作装配来源。

## 4. 数据模型：一篇一卷

`src/data/papers/<方向>.json`（新增目录，与 `quiz/`、`interview/` 同级同构，方向文件名即方向 slug）：

```jsonc
{
  "noteId": "java/intermediate/concurrent/04-synchronized",
  "title": "synchronized 与锁升级 · 本篇测一下",
  "questions": [
    {
      "id": "sync-p01",
      "kind": "recall",              // recall 小节直考 | diverge 发散追问 | relate 相关性
      "type": "single",              // single | multiple | judge
      "section": "JDK 6 的重大优化：锁升级",  // 必须逐字命中本篇某个 ##/### 标题
      "q": "偏向锁解决的是哪一类竞争场景？",
      "options": ["……", "……", "……", "……"],
      "answer": [1],
      "quote": "偏向锁针对「始终由同一线程获取」这一场景……",  // 正文逐字引文，非转述
      "why": "偏向只省 CAS、没做真正的同步，出现第二个线程竞争就要撤销……"
    },
    {
      "id": "sync-p06",
      "kind": "interview",           // 面试题口径：考「说得出口」，答案给结论 + 机制
      "type": "single",
      "section": "synchronized vs ReentrantLock",
      "q": "面试官问「为什么还要用 ReentrantLock」，你答哪三点？",
      "options": ["……"], "answer": [0],
      "quote": "……", "why": "……"
    },
    {
      "id": "sync-p08",
      "kind": "relate",
      "type": "judge",
      "section": "底层：monitor 与对象头",
      "neighborId": "java/advanced/jvm/03-object-layout",  // 相关性的另一头
      "q": "锁状态记录在对象头里，所以加锁会增加对象大小——对吗？",
      "options": ["正确", "错误"], "answer": [1],
      "quote": "……", "why": "mark word 里复用既有字段的位，不额外增长……"
    }
  ]
}
```

**每题固定七字段**：`id/kind/type/section/(relate 再加 neighborId)/q/options/answer/quote/why`。约束：

- 一题一`kind`，`recall` ≥ 3 题且必须**分属不同小节**（否则等于把一个小节问两遍）；
- `diverge` = 仍在本篇正文范围内，但考边界、参数、反例与「为什么不是另一种做法」（对齐现有难度 4–5 档的写法）；
- `relate` ≤ 2 题，且 **答案的 `quote` 仍取本篇**（不能取邻篇），否则越回 R3 的毛病；`neighborId` 必须是图谱里真实存在且能解析为笔记的 id（事实 8 提示：34 个图谱节点 href 指向分类页或跨方向快捷节点，这类要排除）；
- 全卷 5–10 题，`single`/`multiple`/`judge` 至少出现两类，`kind` 至少覆盖 `recall` + 另一种。

## 5. 闸门：`scripts/paper-verify.mjs`（挂进 `pnpm verify:docs`）

反幻觉靠断言，不靠自觉。**落地口径（M1 实跑）**：下列 6 条拆成脚本里的 **9 项**——1→第 4 项、2→第 5 项、3 与 4→第 6 项、5→第 2/3/8/9 项，另把「noteId 与方向可达」独立成第 1 项、「relate 邻居真实」独立成第 7 项、方向覆盖空转守卫独立成第 9 项。**第 4 条只做到机械可查的强度**：判据实现为「错误选项文本（≥6 字）不得逐字出现在同题引文里」，语义级的「被引文否定」无法静态判定，仍靠写题人自觉与 §5 之外的评审。逐卷逐题判红项：

1. **锚点真实**：`section` 逐字等于该篇 `##`/`###` 标题行去掉前缀后的文本（脚本直接读 mdx，与 §1 事实 7 同一解析口径）。
2. **引文逐字**：`quote` 去空白后必须是该篇正文的**连续子串**（不是转述，不是拼接）。这一条同时抓住「编事实」与「改写成自己话后写歪」。
3. **答案合法**：`answer` 下标在 `options` 范围内；`judge` 固定两项；`multiple` ≥2 个正确项。
4. **干扰项不自打**：任一错误选项不得被**同题 `quote`** 直接否定（沿用演进台账第 243 轮那条写题纪律，题库侧已踩过）。
5. **形状与去重**：题数 5–10、`kind`/`type` 覆盖满足 §4、`id` 全局唯一；并与 `src/data/quiz` 按题面做三清单比对，**`q` 文本不得与全局题库任何一题重合**（防「测一下」退化成题库副本——这正是用户区分出来的那两个东西）。
6. **空转守卫**：`noteId` 必须存在于内容集合（防笔记改名后卷变孤儿）；新增方向文件后不许留下没有对应笔记的卷。

沿用 `interview-verify.mjs` 第 9 项的 `KNOWN_MISSING` 覆盖棘轮做法：M1 只登记试点三篇，扩量时逐批把篇目从「已知缺失」名单里删掉，**不允许新方向整块空转**。

## 6. 界面与交互

- **入口**：`src/components/starlight/Footer.astro` 内与 `ProgressMark` 同层，复用现成的笔记页判定（`entry.data.level !== undefined` → `noteId`），只在有卷的笔记页渲染。
- **形态**：收起态一行「测一下 · 这一篇的 N 道题」；点击展开，逐题作答，提交后立即显示 `answer` + `why` + 「依据 · §section」并给跳转链接（`section → slug` 用 `Astro.locals.starlightRoute.headings` 现取，Starlight 0.42 的 `MarkdownHeading` 为 `{depth, slug, text}`，不自造 slug 规则）。
- **末屏**：只列「哪几个小节没答对」，每行一个回读锚点。**不显示分数、不写 localStorage**（「成绩不重要」）。因此**不接** `src/lib/quiz-store.ts`，也不新增 `paper-store.ts`——少一个存储层，少一类状态 bug。
- **无卷的笔记**：不渲染入口（不做「测验待补」占位；占位会把没做的内容成本暴露给读者）。83 篇 0 题的事实只影响推进排期，不影响界面。

## 8. 与无人值守轮次的接法（推荐但不擅改）

## 10. 风险与被否决的选项

| 风险 | 处置 |
|---|---|
| 出题与正文漂移（写了正文里没有的东西） | §5 断言 2「引文逐字命中」当场判红，不放行 |
| 笔记改写后卷失效 | §5 断言 1/6 随 `verify:docs` 每次构建判红；改正文与改卷同轮提交 |
| 与全局题库重复劳动 | §5 断言 5 三清单比对；题库继续承担「跨篇轮考」，卷承担「当篇检测」，分工写进 M2 的规范文本 |
| 数据体量增长（3,997 题 ≈ 全站 JSON 新增一块） | 卷按方向分文件、按需加载（只加载当前笔记那一份，岛屿 props 传入单卷，不广播全量） |

**否决**：① 用现题库抽 3 题交差（不符 5–10，也不符「当篇发散相关性」，且字段缺来源理由）；② 用 mermaid/summary 数据自动生成题（那是结构图，不是检测）；③ 做分数/等级/连续打卡（用户明确「成绩不重要」，且新增存储层只带来状态 bug 面）；④ 在 `quiz/` 里加字段复用同一份数据（会把「全集」和「当篇卷」两种语义焊在一张表上，闸门也得分叉）；⑤ 浏览器端调模型（无服务端，且无引文校验能力）。
