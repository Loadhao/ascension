# 无人值守轮次配方

> 定时任务（Automations：「知识库无人值守演进」）每次触发只推进**一轮**。本文件是那一轮的
> 唯一作业规范：定长、可机检、不存具体内容清单——候选一律用命令现算，避免清单过期。
> 阶段目标、轮次记录、待用户决策仍在 `docs/evolution.md`（它是轮次编号的唯一真源）。
> 人工修改本文件即视为最新事实，技能照办。

## 0. 开工必做（顺序不可变）

1. `git pull --ff-only`；失败（远端分叉）→ 本轮 abort 并记入「待用户决策」，不做 merge。
2. `git status --porcelain` 定界：他人未提交改动一律绕开，**绝不 stage、绝不 commit**，
   也不与它抢同一文件。
3. `pnpm verify:docs` 取基线。不绿 → 本轮直接算 D 车道（修基线优先于一切新产出）。
4. 读 `docs/evolution.md` 的「当前阶段目标」+ 最近 5 条轮次记录 + 「待用户决策」，
   读 `docs/coverage-deepening.md` 队列头部，读 `docs/content-roadmap.md` §2 当前批次头部。
   （内容优先级以 roadmap 为真源，它是用户 2026-09-25 的人工规划——evolution.md 里
   「若用户另有人工规划（如内容路线图），人工修改本文件即视为最新事实」指的就是这份。）

## 1. 车道与游标

`n =` `docs/evolution.md` 里最大轮次号 + 1（当前为 169）。游标不落文件，漏跑或崩溃后自愈。

| `n mod 6` | 车道 | 本轮产出 | 单轮上限 |
| --- | --- | --- | --- |
| 1、4 | **A 新章节** | **2 篇**笔记 + 各自三件套（侧边栏 / 图谱节点 / 分类页）+ 各自本篇卷 1 套 | ≤8 文件（卷允许 +2；走 roadmap 条目完整落点时放宽到 12，只放开 A） |
| 2 | **B 影像资产** | **2 条**配音视频 **或** 1 条视频 + 1 张导出图卡，挂到 ≤4 篇笔记 | ≤10 文件、媒体 ≤12 MB |
| 3 | **C 题库** | **2 套本篇卷**（各 5–10 题，append 到 `src/data/papers/<方向>.json`）**或** 1 套卷 + 3 道题 **或** 6 道题（`src/data/quiz/<方向>.json`），**优先卷** | ≤8 文件 |
| 5 | **D 体检与工具** | **2 项**真实发现的修复，或 1 项修复 + 1 个脚本/闸门增强 | ≤8 文件 |
| 0 | **E 面试考点卡** | **4 张**考点卡（append 到 `src/data/interview/<方向>.json`；可同方向落一份 JSON，也可 2+2 跨两个方向） | ≤8 文件 |

**每轮必含一项内容增量（用户 2026-09-25 指令，2026-09-29 二次强调「必须强制、不能偷懒」，硬约束）**：一轮的产出里必须有至少一项
面向读者的知识资产——新章节 / 新考题 / 速答手册新行 / 新图，**不允许出现「只加了视频」
或「只改了工具脚本」的纯技术轮**。B 与 D 车道在主产出之外，附 1 道考题或 1 条速答行即算
满足（该附加允许超出本车道文件上限 1 个文件）。**体检、闸门、候选登记、台账维护、媒体派生
本身一律不算内容增量**；任何车道在任何情况下（含 D 车道体检全绿的轮次）都不得产出
「零知识资产」的轮次，宁可当轮改走 §3 降级阶梯补内容。**此约束由 `scripts/round-content-verify.mjs`
（`pnpm verify:docs` 末位第 10 个脚本）机器执行**：按台账最大轮次号找该轮全部提交的文件并集，
任一路径落在内容区（`src/content/docs/`、`src/data/quiz|papers|interview/`、`src/data/viz/flows|summaries.ts`）
即检出，全落在媒体/脚本/台账则判红——少了就当轮补产出，不是选择性跳过。

> **2026-09-29 用户指令「加量，每次每车道都要加」**：上表各车道单轮产出**全部翻倍**
> （A 1→2 篇、B 1→2 条、C 1→2 套卷或 3→6 题、D 1→2 项、E 2→4 张），文件上限相应放宽。
> 翻倍后仍按各自取点规则逐条复算，**候选不足时不硬凑**：缺的份额按 §3 降级阶梯取下一个
> 有证据的车道补齐，宁缺毋滥约束不变。E 车道由此放开「每轮必须同方向」旧约束
> （原约束是 ≤4 文件与三处同步相减的产物，上限 ≤8 后不再成立）——4 张可同方向落一份
> JSON，也可 2+2 跨两个方向（每方向仍须同步删 `KNOWN_MISSING` 或按已有卡方向处理）。

> 车道表沿革：影像阶段（2026-09-23 起）曾把 B 排两格以快速铺形态；形态已被站内动画
> 派生路线跑通并连续产出后，用户于 2026-09-25 要求把其中一格还给 A——按本节自述的
> 旋钮改表即可，不需要改技能。**2026-09-28 用户新增 E「面试考点卡」车道（形态设计见
> `docs/superpowers/specs/2026-09-28-interview-cards-design.md`），模数由 5 改 6**：
> A 保留两格（1、4），故**每循环仍出 2 篇新章节**，占比由 2/5 降为 2/6（40%→33%），
> B、C 各 1 格不变，D 由 1/5 降为 1/6，新增 E 1/6。

## 2. 各车道选题（命令现算）

**B/C/D/E 四个车道的候选池由一条命令算出**（含下一轮编号与车道判定），**不要手工维护清单**：

```bash
node scripts/evolution-candidates.mjs [--top 8]
```

它输出：既无图又零题的笔记、纯文字无图笔记、有图但零题笔记、已有动画未出片的队列
（B 车道）、`coverage-deepening.md` 队列头部（C 车道）、带题库却零考点卡的方向（E 车道），
并打印「下一轮 = 第 n 轮 → 车道 X」。
2026-09-23 实测：笔记 535 篇、89 篇无图、33 篇双缺、421 篇有题、44 支动画、2 个影像资产。

> 唯一例外是 A 车道：它的**首要**取点源是 `docs/content-roadmap.md` §2 当前批次——那是
> 人工维护的规划（用户改本文件即视为最新事实），不受「不手工维护清单」约束；脚本清单
> 退为它的兜底池。B/C/D/E 四车道的取点规则不变。

**A 新章节**——按以下三级顺序取点，取到即停：

1. **`content-roadmap.md` §2 当前批次头部第一条非 `done` 条目**（2026-09-25 起为第一优先）。
   条目自带落点、轴、教学问题与证据，照写即可；**若写到一半发现教学问题答不出、或证据
   已被并行会话推翻**（目标分类已有同主题专篇），就地删该条目并按 §3 降级，不硬凑。
2. 上面命令的「既无图又零题」池（33 篇，补一篇两种缺口都收）——roadmap 批次清空或
   该轮条目不可写时用这一级。
3. 纯文字无图笔记池——最后兜底。

无论哪一级，都**先核实是真缺口**：看目标分类 `index.mdx` 大纲与既有篇目，避免重复写作；
篇数少但覆盖深的方向不算缺；落在 roadmap §4「已饱和清单」里的主题一律不写，改为互链。

> 尺寸例外：一条 roadmap 条目的完整落点本身就超过基本文件配额（正文 + 分类页 +
> 侧边栏 + 图谱 + 题库 + 速答行 = 6），故 **A 车道按 roadmap 条目执行时按条目数放宽**
> （1 条 ≤6、翻倍后 2 条 ≤12），且只放开 A；B/C/D 三车道上限不变。这是用户 2026-09-25 定向内容规划带来的尺寸改动（2026-09-29 随全面翻倍同步调整）。

**B 影像资产**——从「已有动画未出片」队列取一支，优先过程型经典（链路/握手/生命周期）。
产法与硬约束照 `src/content/docs/guide/diagrams.mdx`「配音短片与图卡」一节执行
（`media-capture` → `media-encode` → 回填真实尺寸时长 → 笔记 `.mdx` 引用）。
三条踩过的坑必须守住：**帧尺寸不齐会让逐帧切片跨分辨率拉伸**（capture 已自动把逐帧
说明区钉成等高，别绕过它手工截图）；**ffmpeg concat demuxer 对图片的 `duration`
指令不可靠**（实测 10 帧被压成 3 段，只能逐帧切片再无损拼接）；**站点 `:root` 是暗色
基准**，截图前要显式写 `document.documentElement.dataset.theme='light'`，
只设 Playwright 的 `colorScheme` 没用。

**C 题库**——默认产出改为**本篇卷**（用户 2026-09-29 批准，设计见
`docs/superpowers/plans/2026-09-29-note-page-quiz.md`）：从 `coverage-deepening.md` 队列头部取
**一篇笔记**，读正文后出 5–10 题 append 到 `src/data/papers/<方向>.json`，七字段
`id/kind/type/section/neighborId/q/options/answer/quote/why`，`kind` 取 `recall`（小节直考，
≥3 题且**分属不同小节**）/`diverge`（正文内发散追问）/`relate`（图谱相关性，≤2 题且引文仍取本篇）/
`interview`（面试口径，≥1 题）。硬约束：**`section` 必须逐字等于该篇某个 `##`/`###` 标题、
`quote` 必须是该篇正文的连续原文**（去空白与 `**` 后逐字命中）、题面不得与全局题库重合
（「测一下」不是题库的子集）——九条判红全部由 `scripts/paper-verify.mjs` 卡住，补卷后要把该方向
从其 `KNOWN_MISSING` 删项。取不到合格宿主笔记时降级为原路线（3 道全局题）。
原全局题库红线仍适用：取队列头部 3 条，遵守 `coverage-deepening.md` 的「新题红线」：
考点必须与该笔记已有题不同、字段沿用所在文件格式、`judge` 固定 `["正确","错误"]`、
新题一律带 `difficulty`。收尾按该文件规则销号并追加 2~4 条新条目。
`noteId` 写错不会报错、只会静默 404，已由 `scripts/quiz-verify.mjs` 卡住。

**E 面试考点卡**——从「带题库却零考点卡的方向」池取（勘察脚本 E 段现算，口径与
`scripts/interview-verify.mjs` 第 9 项一致），每轮 **4 张**（2026-09-29 翻倍；2+2 跨方向时每方向照旧三处同步），优先用户 2026-09-28 点名的重点：
**Java 后端与 AI 相关方向优先，前端（vue/react/typescript/js）排最后**。一张卡只服务一个
`noteId`，七字段 `id/noteId/group/difficulty/q/intent/answer/followup` 按纯文本写（不得出现
反引号与 `**`），事实**一律取自该笔记正文**——正文没写的就不进卡（宁可少出，不外推、不编数字）。
三段各自的任务不同，缺一段即视为潦草：`intent` 写「这一问在筛什么、短板在哪、区分度落在哪一句」
（不许复述题干），`answer` 写成可以直接说出口的答话（结论先行 + 至少一个具体机制/参数/可查的数字），
`followup` 写「大概率被追问什么 + 一句应对口径」。**三段都要按 `\n` 拆成「一块一句」的话块，不许整段长文**
（`intent` 2~3 块、`answer` 3~5 块、`followup` 2~3 块，每块 ≤40 汉字，`answer` 首块 ≤24 汉字且必须是结论句）——
渲染端按块加序号、三段各配一个语义色（① 筛什么 violet / ② 怎么说 teal / ③ 怎么接 amber），
由 `interview-verify.mjs` 第 10 项判红；**「不潦草」不等于「成段」，一整段说不出口的话没有记忆价值**
（用户 2026-09-28 反馈「回答的内容板块不清晰、看起来费劲、不能长篇大论」，第 219 轮据此把首批 6 张的答话
从 190~255 汉字的整段压成 107~150 汉字的话块）。**同篇第二张卡须按 C 车道同款三清单复算**
（既有卡的题干 / 讲解三段都读一遍），撞车就换宿主或换角度，不硬凑。
落盘后**同步 `coverage-deepening.md` e 类队列**：销掉本轮补上的方向、按空转守卫剩余清单追加；
每补一个方向就要把该方向从 `interview-verify.mjs` 的 `KNOWN_MISSING` 删项（清单过期会判红）。
`noteId` 写错同样只静默 404，已由该闸门卡住。

**D 体检与工具**——`pnpm verify:docs`（一致性 12 项 + mermaid 语法 + 考点卡 10 项 + 题库 9 项 + 影像 7 项 + 本篇卷 9 项，共 47 项）
与 `node scripts/mermaid-contrast-verify.mjs`（需 `pnpm preview`）的输出就是候选池：
修一处真实发现，或给闸门加一条能判红的检查。**「四道全绿无可修」时不得以「登记候选」抵充产出**——
主产出照旧落体检修复或闸门增强，并**必须**按 §1 附 1 道考题或 1 条速答行作内容增量；
无体检可修的轮次改走 §3 降级（D→…之外的等价内容车道）补内容，不允许零知识资产轮次。

## 3. 降级阶梯（「禁止空转」与「宁缺毋滥」的分工）

主车道按上面命令取不到合格候选（或候选会写成重复内容）时，按 **A→B→C→D** 顺序
取下一个有证据的车道执行，并在轮次记录里写明退位原因与勘察命令输出。
D 车道恒有产出，故一轮必定落一个 commit。

两句话记牢：**空转禁令约束「有没有产出」，宁缺毋滥约束「产出选谁」**——
凑数的低质内容不是产出，是负债。

## 4. 收尾必做（缺一即本轮未完成）

1. 验证闸门：`pnpm build` → `pnpm verify:docs` → 动过图表/媒体再加
   `node scripts/mermaid-contrast-verify.mjs`（须 0 处低于 4.5:1）与
   `node scripts/media-verify.mjs`。任一不过 → **整轮回退**（`git checkout --` 自有文件、
   删除自有新增），不提交不推送，原因记入「待用户决策」。
2. 提交：`git add <自有路径>` → `git diff --cached` 核对暂存内容（发现他人改动立即中止，
   改用 `git add -p` 或绕开）→ `git commit -m "..." -- <自有路径>`，
   **禁止裸 commit、禁止 `git add -A`/`.`**。
3. `git push origin main`（AGENTS.md 已规定不等用户确认；被拒则 fetch + rebase 后重验再推）。
4. 在 `docs/evolution.md`「轮次记录」**顶部**追加一条：`### 第 n 轮（日期，车道 X）：`
   + 选题证据（含勘察命令与输出数）+ 内容要点 + 验证数字（页数/图块数/体检项数）+
   下一轮入口。同轮更新「候选项」表状态。
5. C 车道另需销号/追加 `docs/coverage-deepening.md` 队列。
6. E 车道收尾三处同步：`src/data/interview/<方向>.json` 追加卡（**纯追加、按该文件既有排版做
   文本级插入**）→ 把补上卡的方向从 `scripts/interview-verify.mjs` 的 `KNOWN_MISSING` 删项
   （不删会在下轮判红「存量清单过期」）→ 在 `docs/coverage-deepening.md` e 类队列销号/追加。
7. A 车道按 roadmap 条目落地后：回 `docs/content-roadmap.md` §2 把该条目状态改
   `done <日期>`（写真实笔记路径，条目被删要写明删因），并按该文件 §2 末尾「固定动作」
   向 `docs/coverage-deepening.md` d 类入队该新篇的第二题；B1 全 `done` 时按 §3 复评，
   不自行展开 B2。

## 5. 停止条件（触发即收尾并批量上报，不机械重试）

- 同一症状构建失败连续 2 次 → 回退、不推送，在 `evolution.md` 顶部写
  `🛑 车道 X 连败 2 次，已暂停产出待裁决`。
- 无法安全定界的他人改动（同一文件同一区域）→ abort 本轮。
- 需要真实用户数据才能裁决方向、涉及付费/凭据/对外发布、或出现两个贡献相当的
  产品方向 → 记入「待用户决策」后收尾。
- 累计 3 个 🛑 → 提示用户到 Automations 面板 `disable` 本任务。
- 连续两轮未获得新证据 → 输出阻塞分析并停止。

## 6. 轮次编号一致性

- `evolution.md` 是**唯一全局轮次真源**，从 169 续号，不重排、不合并历史编号。
- `coverage-deepening.md` 降为纯队列数据，**禁止自增全局轮次**；其自身历史里的
  「题库深化第 N 轮」是二级序号，在它的「已完成记录」里继续自增。
- C 车道的记录行写成「第 170 轮｜车道 C｜题库深化第 61 轮」，两套编号靠这一行对齐。
- 并行会话压缩过历史详情（见 evolution.md 的压缩说明）：接受，不恢复——
  内容本身在 git 历史里可查。

## 7. 文档体量维护

- 收尾在「轮次记录」顶部追加记录后，若 `docs/evolution.md` 超过约 **150KB**：把最近 5 轮以外的
  轮次记录压缩为每轮单行（保留轮次号、日期、车道/模式与真实性标注、一句核心结论），并在
  「轮次记录」标题下留一行压缩说明（写明压缩日期与「详情见 git 历史」）。
- 压缩红线：不改轮次号、不给缺号轮次虚构补齐（如第 180 轮整轮回退无独立记录）；「候选项」
  「经验与判断沉淀」「待用户决策」三个区块不参与压缩；已压缩过的单行不再扩写。
