MongoDB **开箱默认无认证**——`mongod` 起来就能连，这是无数泄露事故的
起点（公网未认证实例扫描已成产业）。认证与角色是 MongoDB 上生产的
第一道必答题（SSH 篇的安全思想在数据库层的重放）。

## 认证：SCRAM 挑战响应

- **SCRAM-SHA-256**（默认）：密码不落库明文（存派生值），认证走
  挑战响应——**密码不在线路上传输**（类似 SSH 的签名挑战思想）；
- 企业级：x509 证书认证（TLS 双向）或 LDAP/Keberos 集中认证
  （对接企业账号体系，SSH 篇的 LDAP 呼应）；
- **启用认证的前置**：先建管理员账号再 `--auth`（否则锁死自己）；
  副本集还要内部认证（keyfile/证书——节点间互信）。

## 角色：内置角色与最小权限

| 角色 | 能力 | 给谁 |
| --- | --- | --- |
| read | 只读指定库 | 报表/分析账号 |
| readWrite | 读写指定库 | **应用账号（默认该给这个）** |
| dbAdmin | 库管理（索引/校验） | DBA 工具账号 |
| userAdmin | 管理用户与角色 | 权限管理账号 |
| clusterAdmin | 集群管理（副本集/分片） | 运维账号 |
| root | 超级 | 极少数人 |

- **应用账号只给目标库的 readWrite**——绝不给 dbAdmin/root（最小
  权限，与 SSH 篇的 capabilities 同思想：拆解全能、按需授予）；
- **自定义角色**：内置粒度不够时按"集合+操作"细拆（如只读写
  orders 集合）；
- 多角色取并集——角色设计避免"为了省事给大角色"。

## 网络与传输边界

- **bindIp**：默认绑定 127.0.0.1——公网暴露 = 未认证实例扫描产业
  的猎物（SSH 篇的入口收敛同思想）；
- **TLS**：传输加密（x509 双向认证可与 TLS 合并）；
- 分层防线：bindIp 收敛 → 认证 → 角色 → 集合级权限 → 字段级
  （视图/列裁剪）。

## 高频追问速答

- **忘了建管理员就开了 --auth 怎么办？** localhost exception：
  首次无用户时 localhost 连接可建第一个管理员（有时间/人数限制）
  ——了解但别依赖，部署脚本里先建账号。
- **应用连接串要不要 admin 账号？** 绝不——应用账号只授目标库
  readWrite；连接串泄露时的爆炸半径等于账号权限。
- **审计日志呢？** 企业版有审计（ATLAS/自建用旁路日志）——操作
  留痕与 IM 篇的审计同思想。

## 小结

- 默认无认证是 MongoDB 第一坑：启用认证 + bindIp 收敛 + TLS 是
  上生产三件套。
- 角色最小权限：应用 readWrite、管理分开、自定义角色细粒度——
  capabilities 思想在数据库的落地。
- 副本集的内部认证（节点互信）与客户端认证是两条独立的线。
