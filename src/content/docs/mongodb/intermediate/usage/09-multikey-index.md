"MongoDB 数组字段能建索引吗？"——能，而且**自动**：对数组字段建普通
索引，MongoDB 自动变成**多键索引**（multikey）——数组每个元素都是
一个索引项。这是 MongoDB 索引的基础特色，但有两条硬限制要知道。

## 多键化：每个元素一个索引项

```javascript
db.posts.createIndex({ tags: 1 })
// 文档 { tags: ["mongodb", "database"] } 在索引里产生两个条目：
//   "mongodb" → 该文档
//   "database" → 该文档
db.posts.find({ tags: "mongodb" })   // 走索引，毫秒级
```

- 查询"包含某 tag 的文章"直接命中索引项——数组查询的索引与标量
  无缝；
- **反向也索引**：按数组中的任意元素都能查。

## 两条硬限制

1. **一个查询只能用一个多键索引**：`{ tags: "a", categories: "b" }`
   两个数组字段各有索引——优化器只能选一个，另一个过滤靠回表——
   数组对数组的交集查询要靠 **$elemMatch + 应用层**或聚合；
2. **多键 + 复合索引的边界**：复合索引**至多一个**数组字段
   （`{ a: 1, b: 1 }` 里 a、b 都是数组则无法创建）——两个数组字段
   的组合索引在数学上会产生笛卡尔积爆炸。

## 与 $elemMatch 配合

查询"数组元素整体满足条件"（而非单字段命中）用 $elemMatch：

```javascript
// scores: [{ subject: "math", score: 90 }, ...]
db.students.find({ scores: { $elemMatch: { subject: "math", score: { $gte: 90 } } } })
```

- $elemMatch 保证**同一元素**同时满足多个条件（没有它，
  `{subject: math, score: 90}` 会被解释为"数学 60 分"+"英语 90 分"
  也匹配——经典 bug）。

## 高频追问速答

- **多键索引的代价？** 数组越长，索引项越多（N 元素 = N 个索引项）
  ——写放大与数组长度成正比；超大数组（百万元素）建议桶模式拆分
  （Schema 模式篇）。
- **多键索引能覆盖查询吗？** 受限：查询字段与返回字段都在索引且
  满足多键规则时可覆盖，但数组字段返回的是数组本身——覆盖查询对
  多键不友好。
- **嵌套文档数组能索引吗？** 能（`scores.score` 点路径自动多键），
  但**嵌套数组中的嵌套数组**无法索引（一层嵌套限制）——深层结构
  查询用 $elemMatch + 点路径组合。

## 小结

- 数组字段自动多键化：每个元素一个索引项，数组查询无缝走索引。
- 两条硬限制：一次查询一个多键索引；复合索引至多一个数组字段。
- $elemMatch 是"同一元素多条件"的正确姿势——没有它就有跨元素
  假匹配的经典 bug。
