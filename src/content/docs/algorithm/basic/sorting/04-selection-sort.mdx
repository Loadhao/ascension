选择排序（Selection Sort）的思路最像人找东西：**每一轮把未排序区间扫一遍，选出最小的元素，与区间头部交换**。
n - 1 轮后全部就位。它的行为非常「固执」：不管输入长什么样，**比较次数恒定 n(n-1)/2，交换至多 n - 1 次**——交换次数是所有排序里最少的一档。

## Java 实现

```java
public static void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int min = i;                            // 先假设头部最小
        for (int j = i + 1; j < a.length; j++) {
            if (a[j] < a[min]) min = j;         // 只记录位置，不动元素
        }
        if (min != i) {
            int t = a[i]; a[i] = a[min]; a[min] = t;
        }
    }
}
```

注意它和冒泡的关键差别：内层循环**只比较、不交换**，最小值的位置记在 `min` 里，一轮收尾才换一次。
如果内层边比边换，就成了「交换版选择排序」——比较次数没少，交换次数却涨到 O(n²)，白白多干活。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间（所有情况） | O(n²) | 比较次数恒为 n(n-1)/2，输入是否有序不影响 |
| 空间 | O(1) | 原地，一个 min 下标加一个临时变量 |
| 交换次数 | **O(n)** | 每轮至多一次交换，交换次数最少的一类排序 |
| 稳定性 | **不稳定** | 头部与远处最小值的交换会跨越相等元素 |

## 面试要点

- **为什么不稳定**：经典反例 `[5a, 5b, 2]`——第一轮 5a 与 2 交换，越过 5b，两个 5 的相对次序被打乱。若要稳定版，得把「交换」改成「把最小值前插、区间整体右移」，但那又变成了 O(n²) 次移位。
- **交换次数最少的价值**：比较廉价而「交换/移动」昂贵的场景（元素很大、写在 Flash/EEPROM 这类写寿命有限的介质上），O(n) 次写操作是它独有的优势。
- **有序输入也不加速**：`[1, 2, 3, ..., n]` 依然要做满 n(n-1)/2 次比较——没有提前退出机制，这是它与冒泡（swapped 提前退出）、插入（近乎有序 O(n)）最大的差距。
- 堆排序可以看作选择排序的升级版：同样是「每轮选最大放到末尾」，但用堆把「选最值」从 O(n) 降到 O(log n)。
