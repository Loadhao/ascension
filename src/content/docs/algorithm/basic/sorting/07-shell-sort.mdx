插入排序慢的根源：**元素一次只能挪一格**，小值落在数组右端时要一格一格爬回来。
希尔排序（Shell Sort，按发明者 Donald Shell 命名）的解法简单粗暴：**先按间隔 gap 分组做插入排序，
gap 从大到小递减，最后一步才是普通的插入排序（gap = 1）**——此时远距离逆序已被大 gap 轮次消掉，
数组近乎有序，最后一轮接近 O(n)。

## Java 实现

```java
public static void shellSort(int[] a) {
    int n = a.length;
    for (int gap = n / 2; gap > 0; gap /= 2) {   // 常用序列：n/2 逐次减半
        // 组内插入排序：把「相邻一格」改成「相隔 gap 格」，逻辑与插入排序完全同构
        for (int i = gap; i < n; i++) {
            int key = a[i];
            int j = i;
            while (j >= gap && a[j - gap] > key) {
                a[j] = a[j - gap];                // 比 key 大的组内元素右移 gap 格
                j -= gap;
            }
            a[j] = key;
        }
    }
}
```

内层就是插入排序，唯一区别是比较对象从 `a[j - 1]` 换成 `a[j - gap]`、移动步长从 1 换成 gap。
gap 序列是性能关键：`n/2` 减半最简单；**Knuth 序列 `1, 4, 13, 40, …（3h + 1）`** 实测更好，
写成 `int h = 1; while (h < n / 3) h = 3 * h + 1;` 后逐层 `h /= 3`。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间 | 依赖 gap 序列 | 理论上界 O(n²)（减半序列）；Knuth 序列 O(n^1.5)；经验约 O(n^1.3) |
| 空间 | O(1) | 原地，插入排序的直接推广 |
| 稳定性 | **不稳定** | 跨组交换会越过相等元素 |
| 定位 | 中小规模、要求 O(1) 空间 | 比简单 O(n²) 快不少，又没有快排的递归栈 |

## 面试要点

- **为什么 gap = 1 那轮很快**：前面的轮次保证「相距 2 的元素有序」等粗粒度有序性，逆序对已被大步消除——这正是希尔排序的核心洞察：**先粗调后微调**。
- **gap 序列不能有公因子**：若序列是 `8, 4, 2, 1` 这类，不同轮次的分组大量重合（都是 2 的倍数位置），前面轮次做重复功——好的序列（Knuth、Sedgewick）刻意让相邻 gap 互质或低公因子。
- **为什么不稳定**：大 gap 交换时，相等元素可能在不同的组里被交叉换位。
- 与快排/归并的取舍：数据量中等（几千到几万）、内存敏感、不想写递归时它是个干净的中间档；更大的数据交给 O(n log n) 算法。
