比较排序有一个数学下界：**基于两两比较的排序最坏至少要 Ω(n log n) 次比较**（决策树论证，n! 种排列至少要 log₂n! 次比较才能区分）。
计数排序（Counting Sort）之所以能突破到线性，是因为它**根本不比较**：值本身就是数组下标——
数出每个值出现几次，再按值的顺序把输出数组填回去，耗时 **O(n + k)**（k 是值的范围）。

## Java 实现

上面演示的是「直接展开」简化版（适合基础类型）；通用版多一步**前缀和 + 倒序回填**，用来保证稳定性：

```java
/** 稳定计数排序：a 的值域 [min, max]，按排序结果写入 out */
public static void countingSort(int[] a, int[] out) {
    int min = a[0], max = a[0];
    for (int v : a) { min = Math.min(min, v); max = Math.max(max, v); }
    int k = max - min + 1;

    int[] count = new int[k];                     // 1. 计数
    for (int v : a) count[v - min]++;

    for (int i = 1; i < k; i++)                   // 2. 前缀和：count[i] 变为「值 <= i+min 的元素个数」
        count[i] += count[i - 1];                 //    即每个值在输出数组中的结束下标（开区间）

    for (int i = a.length - 1; i >= 0; i--) {     // 3. 倒序回填：同值元素按原次序落位 → 稳定
        int v = a[i] - min;
        out[--count[v]] = a[i];
    }
}
```

两个工程细节：**负数与稀疏值域**用 `min` 偏移把值映射到 `[0, k)`；**为什么倒序**——前缀和存的是结束位置，
从右往左扫原数组时，同值的元素后扫到的落在更左边，恰好保持它们原来的相对次序。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间 | **O(n + k)** | 数一遍 + 前缀和 + 回填各一遍；k 是值域宽度 |
| 空间 | O(n + k) | 计数数组 O(k) + 输出数组 O(n) |
| 稳定性 | **稳定**（回填版） | 倒序回填保证；直接展开版谈不上稳定性 |
| 前提 | 整数 / 可映射成小范围整数 | k 与 n 同量级才划算；k ≫ n 时退化（值 0 和 10 亿的两个元素也要 10 亿的计数数组） |

## 面试要点

- **「为什么它不受 O(n log n) 限制」是必考点**：它不做元素间比较，用值直接定位，代价是必须知道值域且值域不能太大——时间换空间的判断题。
- **桶排序是它的一般化**：值域太大时把值域切成若干桶（每桶内部再排序），计数排序相当于「一个值一个桶」；**基数排序**是「按位多轮计数排序」（从低位到高位，依赖每轮稳定），两者常和计数排序打包一起问。
- 典型适用场景：年龄排序、考试分数排序、字节/字符（值域 256）排序——**值域小且已知**是信号。
- 易错点：前缀和后 `count[v]` 的含义从「个数」变成「下一个写入位置的右侧一格」，回填必须先 `--` 再写入；漏掉 `min` 偏移会在负数输入下越界。
