插入排序（Insertion Sort）是整理扑克牌的动作：**左手的牌始终有序，每摸一张新牌，从右往左找到它该插的位置，比它大的牌依次右移腾位**。
它最动人的性质是：输入越接近有序，跑得越快——**近乎有序的数组接近 O(n)**，这一点是 O(n²) 三兄弟（冒泡/选择/插入）里独有的。

## Java 实现

```java
public static void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {       // a[i] 是待插入的 key
        int key = a[i];
        int j = i - 1;
        // 比 key 大的元素整体右移一格，给 key 腾位置
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                        // key 落位：左边都不比它大
    }
}
```

三个手写细节：

- **右移是赋值不是交换**：`a[j + 1] = a[j]` 一条赋值就能腾位，比冒泡的「三次赋值一交换」少一常数——这就是插入排序在实测中几乎总比冒泡快的原因。
- **`key` 要先存下来**：循环里 `a[i]` 的位置会被右移覆盖，不暂存就丢了。
- **边界 `j >= 0` 在 `a[j] > key` 之前**：顺序反了会在 j = -1 时先取 `a[-1]` 越界。

查找插入位置本身可以二分（二分插入排序），把「找位置」降到 O(log n)，但腾位仍要 O(n) 次移位，整体还是 O(n²)，只在比较代价特别贵（如比较字符串）时值得。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间（平均 / 最坏） | O(n²) | 逆序数组时每个 key 都要挪到最前面 |
| 时间（最好） | O(n) | 已有序数组每个 key 只比较一次 |
| 空间 | O(1) | 原地，只需暂存 key |
| 稳定性 | **稳定** | 只在 `a[j] > key` 时右移，相等元素相对次序不变 |

## 面试要点

- **工业排序的小区间兜底**：`Arrays.sort`、TimSort 在区间/小片段（约 16~47 个元素）时都切到插入排序——小数组上它的常数开销低于 O(n log n) 算法，且对「基本有序片段」敏感。快排笔记里的「小区间优化」说的就是它。
- **近乎有序 O(n)**：每轮 key 只需比较一两次就落位，这是「adaptive sorting（自适应排序）」的典型例子；数据流式追加、批量微调后重排的场景就靠这个性质。
- 与冒泡的对比：都是相邻比较的 O(n²)，但冒泡每轮固定扫完整个无序区（比较次数与输入无关），插入的 while 一碰到不大于 key 的就停——**有序前缀越长，插入越省**。
- 与选择的对比：选择排序比较次数固定、交换最少但不稳定；插入比较次数 adaptive、需要写操作但稳定——两者恰好互补。
