二分查找（Binary Search）利用「数组**有序**且支持**随机访问**」两个前提，每次取区间中点与目标比较，
把搜索区间**折半**，比较次数从线性扫描的 O(n) 降到 O(log n)——100 万个元素最多只要 20 次。

## Java 实现

迭代版是首选——没有递归栈开销，边界一目了然：

```java
public static int binarySearch(int[] a, int target) {
    int low = 0, high = a.length - 1;         // 闭区间 [low, high]
    while (low <= high) {                     // 区间非空才继续
        int mid = low + (high - low) / 2;     // 防溢出写法，不用 (low+high)/2
        if (a[mid] == target) return mid;
        if (a[mid] < target) low = mid + 1;   // 目标在右半区
        else high = mid - 1;                  // 目标在左半区
    }
    return -1;                                // 区间为空，未找到
}
```

三个最容易踩的坑，全部出在这几行里：

- **`mid` 的溢出**：`(low + high) / 2` 在两端都接近 `Integer.MAX_VALUE` 时会先加法溢出，
  必须写 `low + (high - low) / 2`。JDK 的 `Arrays.binarySearch` 历史上真踩过这个 bug（JNI 排序大数组场景）。
- **边界是 `low <= high` 还是 `low < high`**：取决于区间定义。闭区间 `[low, high]` 用 `<=`，
  左闭右开 `[low, high)` 用 `<`。混用定义和边界是死循环的主要来源。
- **收缩必须排除 mid**：`low = mid + 1`、`high = mid - 1`。写成 `low = mid` 时，区间长度为 1 的那一轮
  `mid` 不再变化，直接死循环。

## 循环不变量：读懂一切二分的钥匙

上面迭代版的不变量是：**target 若存在，必在 `[low, high]` 内**。

- 初始时区间覆盖全数组，成立；
- 每次比较后，`a[mid]` 已被检查且不等于 target，把它排除出区间仍然成立；
- 循环结束时区间为空 → target 不存在，返回 -1 是正确结论。

面试里的二分变体（找左边界、找右边界、旋转数组找拐点）本质都是换一个不变量，
不变量写对了，边界条件是推导出来的而不是背出来的。

## 常用变体：找左边界（lower_bound）

「第一个大于等于 target 的下标」是最高频的变体，注意它返回的不是命中下标而是插入点：

```java
public static int lowerBound(int[] a, int target) {
    int low = 0, high = a.length;             // 左闭右开 [low, high)
    while (low < high) {
        int mid = low + (high - low) / 2;
        if (a[mid] < target) low = mid + 1;   // mid 及左侧都不够格
        else high = mid;                      // a[mid] >= target，mid 可能是答案，不能跳过
    }
    return low;                               // 第一个 >= target 的下标
}
```

直接用 JDK 时注意 `Arrays.binarySearch` 的返回值约定：找到返回下标；**找不到返回 `-(插入点) - 1`**，
取反减一即还原插入点，这个约定常被忽略。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间 | O(log n) | 每次比较区间减半，n → n/2 → … → 1 |
| 空间 | O(1) | 迭代版原地；递归版 O(log n) 栈开销 |
| 前提 | 有序 + 随机访问 | 链表不行（无法 O(1) 取中点）；流式数据不行 |
| 适用 | 查询远多于修改 | 有序性靠插入/删除维护的代价是 O(n)，动态数据应改用平衡树/跳表 |
