「无序数组找第 K 小」最直觉的做法是排序后取下标，O(n log n)；快速选择（Quickselect）的洞察是：
**找第 K 小不需要整段有序**。借用快排分区——基准每次归位到「它在有序数组中的真实位置」——
归位下标与 K 比一比，**只进入包含答案的那一侧**，另一侧整段丢弃。期望复杂度从 O(n log n) 降到 **O(n)**：
n + n/2 + n/4 + … ≈ 2n。

## Java 实现

迭代版（免递归栈，循环里二选一）：

```java
/** 返回第 k 小（k 从 1 开始）；平均 O(n)，最坏 O(n²)（基准总选到最差） */
public static int quickSelect(int[] a, int k) {
    int low = 0, high = a.length - 1;
    int target = k - 1;                       // 第 k 小 → 有序下标 k-1
    for (;;) {
        int p = partition(a, low, high);      // 基准归位到 p（与快排同一个 partition）
        if (p == target) return a[p];
        if (p < target) low = p + 1;          // 答案在右段，左段整段丢弃
        else            high = p - 1;         // 答案在左段，右段整段丢弃
    }
}

private static int partition(int[] a, int low, int high) {
    // 随机基准避免「已有序输入」持续选到最差基准
    int r = low + ThreadLocalRandom.current().nextInt(high - low + 1);
    swap(a, r, high);
    int pivot = a[high], i = low;
    for (int j = low; j < high; j++)
        if (a[j] < pivot) swap(a, i++, j);
    swap(a, i, high);
    return i;
}
```

与快排唯一的结构差别：快排**两侧都递归**，快选**只走一侧**——单边递归让期望规模按 n/2 等比收缩，这是 O(n) 的全部来源。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间（平均） | **O(n)** | n + n/2 + n/4 + … ≈ 2n 次比较 |
| 时间（最坏） | O(n²) | 基准每次都选到最值（随机化后概率极低） |
| 空间 | O(1) | 迭代版原地 |
| 副作用 | 会打乱原数组 | 分区是交换式的，不能用于「只读」数据 |

## 面试要点

- **Top-K 的双解法对比是必考题**（LeetCode 215「数组中第 K 大」）：**堆** O(n log k) + O(k) 空间，适合流式数据/数据量远大于 K；**快选**平均 O(n) + O(1) 空间，适合内存放得下的批量数据。先问「数据能不能全部载入内存、是否流式」再选型，是加分回答。
- **理论最坏 O(n) 的选择算法**存在：BFPRT（中位数的中位数选基准），但常数大、实现繁琐，工程上几乎都用「随机基准快选」——面试提一句知道即可。
- 快选一次只收敛一侧，所以平均快于快排；但它**不稳定也不保序**，输出「Top-K 但 K 个内部无序」通常可接受，不行就再对 K 个元素排序（O(k log k)）。
- 与堆排序的亲缘：堆笔记里「Top-K 用小顶堆 O(n log k)」的另一半答案就是快选——两个笔记合起来才是完整回答。
