「多次查询区间和」的暴力解每次都从 `l` 累加到 `r`，m 次查询 O(nm)。前缀和（Prefix Sum）的思路是
**把重复的累加提前做掉**：一趟 O(n) 算出 `P[i]` = 前 i 个元素之和，之后任何区间的和都是
**两个前缀值相减**：`sum(l, r) = P[r+1] - P[l]`——一次减法，O(1)。

## Java 实现

```java
int[] prefix = new int[n + 1];                 // prefix[0] = 0 哨兵
for (int i = 0; i < n; i++)
    prefix[i + 1] = prefix[i] + a[i];          // 一趟预处理 O(n)

int rangeSum = prefix[r + 1] - prefix[l];      // 任意区间和，O(1)
```

**哨兵 `P[0] = 0` 是写对的关键**：它统一了「区间从下标 0 开始」的边界——`sum(0, r)` 就是 `P[r+1] - P[0]`，
不需要为左端点写特判。所有前缀类技巧（前缀异或、前缀积）都用同样的哨兵。

同族变体：

```java
// 前缀异或：区间异或 = 两前缀异或相抵（x ^ x = 0）
xorLR = preXor[r + 1] ^ preXor[l];

// 二维前缀和：P[i][j] = 左上角子矩阵和，任意子矩阵和用容斥四项加减
// P[i][j] = P[i-1][j] + P[i][j-1] - P[i-1][j-1] + a[i][j]
// 子矩阵和 = P[x2][y2] - P[x1-1][y2] - P[x2][y1-1] + P[x1-1][y1-1]
```

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 预处理 | O(n) | 一趟累加 |
| 单次查询 | **O(1)** | 一次减法 |
| 空间 | O(n) | 前缀数组 |
| 适用 | **静态数据 + 频繁区间查询** | 元素不变（如 LC 303 区域和检索、LC 304 二维区域和） |
| 失效场景 | 频繁单点修改 + 查询混合 | 改一个元素要重建整个 P；应改用树状数组/线段树（O(log n) 改查） |

## 面试要点

- **与前缀和最搭的组合是「有序性」**：前缀和数组天然单调（元素非负时），「和 ≥ target 的最短子数组」可以先求前缀和再对每个右端点二分找左边界，O(n log n)——对照滑动窗口笔记：正数时滑窗 O(n) 更优，含负数时滑窗失效、前缀和 + 单调队列才是正解。
- **为什么单点修改会毁掉前缀和**：修改 `a[i]` 后 `P[i..n]` 全部失效，重建 O(n)——「查询多修改少」用前缀和，「边改边查」上树状数组，这是标准选型话术。
- 统计类妙用：「和为 k 的子数组个数」（LC 560）= 边扫边查哈希表里 `前缀和 - k` 出现的次数，把前缀和与哈希组合，是高频组合拳。
- 手写坑：数组开 `n + 1` 长度、`P[r+1]` 的 `+1` 别丢——「左闭右闭区间」到「前缀下标」的偏移是这题最多的 off-by-one 来源。
