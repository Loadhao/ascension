合并两个有序链表（LeetCode 21）是归并排序「合并阶段」的链表版，而且比数组版更漂亮——
链表合并**不需要辅助数组**，改指针就行，O(1) 额外空间。核心就是双指针：
比较两条链的头部，较小者接到结果链尾，对应指针前进。

## Java 实现

```java
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode();          // 哨兵：统一「结果链为空」的边界
    ListNode tail = dummy;                    // 结果链的尾
    while (l1 != null && l2 != null) {
        if (l1.val <= l2.val) {               // <=：相等取 A，稳定
            tail.next = l1;
            l1 = l1.next;
        } else {
            tail.next = l2;
            l2 = l2.next;
        }
        tail = tail.next;
    }
    tail.next = (l1 != null) ? l1 : l2;       // 剩余的一条整体接上，不用循环
    return dummy.next;
}
```

两个写题要点：**dummy 哨兵**免去「头节点是谁」的特判；结尾**整段接尾巴**——链表天然连接，剩余部分一个赋值搞定（数组版还得逐个拷贝）。

递归版同样经典，代码最短：

```java
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    if (l1 == null) return l2;
    if (l2 == null) return l1;
    if (l1.val <= l2.val) {
        l1.next = mergeTwoLists(l1.next, l2);  // 1 后接「剩余部分的合并结果」
        return l1;
    } else {
        l2.next = mergeTwoLists(l1, l2.next);
        return l2;
    }
}
```

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间 | O(m + n) | 每个节点恰好被接一次 |
| 空间 | 迭代 O(1) / 递归 O(m+n) | 链表合并无需辅助数组，是链表对数组的核心优势 |
| 稳定性 | 取 `<=` 时稳定 | 与归并排序同源：相等取左 |

## 面试要点

- **归并排序在链表上是「天选」算法**（对照归并排序笔记）：拆分用快慢指针找中段、合并就是本题，全程 O(1) 额外空间且天然稳定——所以「链表排序首选归并」的完整论证由本题 + 找中点两块拼成。
- **K 条链表合并**（LC 23）：两两分治合并 O(N·logK)，或小顶堆每次弹出全局最小 O(N·logK)——「多路归并用堆」正是外排序的核心操作。
- 手写坑：忘写 `tail = tail.next` 会死循环；用 `l1.val <= l2.val` 而非 `<`，除了稳定性还避免两指针都不动的边界。
- 检验理解的小问题：「为什么数组归并要 O(n) 辅助空间而链表不用？」——数组覆盖会丢数据（对照归并排序演示里的腾位交换），链表只动指针。
