判断链表是否有环（LeetCode 141）并找出环入口（LeetCode 142），标准解是 **Floyd 快慢指针**：
slow 一次走 1 步、fast 一次走 2 步。有环则 fast 绕圈「追上」slow 相遇；无环则 fast 先撞到 null。
相遇后把 slow 拉回 head，两指针改为同速前进，**再次相遇的位置就是环入口**——两段推导都值得一字一句看懂。

## Java 实现

```java
/** 有环返回环入口节点，无环返回 null（LC 142，一步到位版） */
public ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;             // 慢指针 1 步
        fast = fast.next.next;        // 快指针 2 步
        if (slow == fast) {           // 相遇：有环
            slow = head;              // 慢指针回起点
            while (slow != fast) {    // 同速前进，再次相遇即入口
                slow = slow.next;
                fast = fast.next;
            }
            return slow;
        }
    }
    return null;                      // fast 撞到 null：无环
}
```

循环条件 `fast != null && fast.next != null` 的顺序不能反——先判 `fast.next` 会在 fast 为 null 时空指针。

## 两段正确性推导

**为什么相遇即有环**：无环时 fast 一路领先直到 null，不可能相遇（fast 始终在 slow 前面）；
有环时 fast 每轮比 slow 多走 1 步，在环内「距离 slow」每轮缩短 1，最多绕一圈必然追上。

**为什么二次相遇在入口**：设头到入口距离为 `a`，环长为 `b`，相遇点距入口 `c`（沿前进方向）。
相遇时 slow 走了 `a + c`，fast 走了它的两倍 `2(a + c)`，多出的 `a + c` 全是绕环的整圈：`a + c = m·b`。
于是 `a = m·b - c`——从**头**走 a 步到入口，等于从**相遇点**走 `m·b - c` 步：绕 m 圈回到相遇点再退 c 步，也正好落在入口。
所以两个指针同速前进，第一次共同落点就是入口。演示里 a = 1（头 1 → 入口 2）、b = 4，可对照验证。

## 复杂度与特点

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 时间 | O(n) | 两段都是线性扫描；fast 总步数不超过 2n + 环长 |
| 空间 | **O(1)** | 两个指针；对比哈希表存访问节点要 O(n) |
| 替代解 | HashSet 记录访问节点 | 更直观但空间 O(n)，且能顺便给出「第一次重复访问的节点」即入口 |

## 面试要点

- **追问链**通常是：判环（141）→ 找入口（142）→ 找链表中点 / 倒数第 K 个——快慢指针家族全是同一招「速度差」，找中点让 fast 走 2 步 slow 走 1 步，倒数第 K 让 fast 先走 K 步。
- 偶数个节点找中点会落在**两个中点里的后一个**（fast 停在 null），要前一个需判 `fast.next.next != null`——细节常被追问。
- 手写坑：`fast.next.next` 前必须确认 `fast.next != null`；Java 里 `==` 比较的是节点引用不是值。
- 环形链表的打印/遍历都要先判环，否则死循环——这也是为什么序列化工具（如 Jackson）默认会检测循环引用。
