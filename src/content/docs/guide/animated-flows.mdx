站点的可视化目前有三档，各有分工：

| 方式 | 机制 | 适合 |
| --- | --- | --- |
| 静态 Mermaid | 构建时渲染 SVG，零运行时 | 结构、关系、层次——「长什么样」 |
| 氛围动画（[连线流动 / 呼吸节点](/guide/diagrams/)） | 纯 CSS，构建时烘焙 | 有方向性的链路——「往哪流」 |
| **步进动画（本页）** | React 岛屿 + 步骤播放器 | 过程与协议——「一步步怎么发生」 |

步进动画补上的是最后一块：**按叙事顺序播放一个过程**。数据包沿着连线行进、
节点随阶段切换状态（琥珀高亮 = 当步动作，灰色 = 已完成）、每一步配一句讲解，
可以播放、暂停、单步、拖进度条。算法笔记里已经用它讲排序和搜索（柱状/树/图等画法），
现在把它扩展到**架构图与流程图**：固定布局的节点 + 沿线行进的数据包 + 状态徽标。

## 示例一：一条 UPDATE 的旅程（架构链路）

MySQL 里一条更新语句要穿过 Server 层与 InnoDB 两套日志，顺序错了就可能丢数据。
静态图能画出组件，但「先写哪个日志、什么时候置 commit」是时间维度的事——放一遍就懂了：

<AlgorithmVizIsland demo="mysql-2pc" />

观察两点：redo log 的徽标从 `prepare` 变 `commit` 的那一步（两阶段提交的核心），
以及最后「返回 OK 之后才后台刷盘」——理解了这两步，崩溃恢复的规则就不用死记了。

## 示例二：TCP 四次挥手（协议时序）

同一套画法换个布局就能讲协议。两个节点、双向弧线、状态徽标，把四次挥手和
「TIME_WAIT 为什么等 2MSL、归谁」演出来：

<AlgorithmVizIsland demo="tcp-close" />

徽标就是 TCP 状态机的迁移轨迹（ESTABLISHED → FIN_WAIT_1 → … → CLOSED），
单步播放时对照看两侧状态什么时候变、为什么变。

## 交互方式

- 组件进入视野后**自动循环播放**，末帧会停留几拍再回头；
- 点**暂停**后可用「上一步 / 下一步」单步细看，进度条可直接拖到任意一步；
- 键盘：聚焦组件后 `←` `→` 单步，空格播放/暂停；
- 五档速率（0.25× ~ 2×）下一帧起生效。

## 怎么新增一个演示

与算法动画同一套模式，三步：

1. 在 `src/data/viz/flows.ts` 写一个 `FlowVizConfig`：`nodes`（固定布局，0~1 归一化坐标，
   可选 `rect` / `cylinder` / `doc` 三种形状）、`edges`（可选弧度 `bend`、虚线、双端箭头）、
   `frames`（每步：节点 `active`/`done`/`dim`、`hotEdges`、沿线 `packets`、状态 `badges` 与讲解文案）；
2. 在文件底部的 `flowDemos` 注册表里挂一个短横线 key；
3. 笔记（`.mdx`）里 `<AlgorithmVizIsland demo="key" />` 引用。

配色全部走 `--algo-*` 主题令牌，亮/暗主题自动适配，写数据时不需要（也不允许）指定颜色。
选型原则与静态图的分工见上表：**讲结构用 Mermaid，讲过程用步进动画**，一篇笔记两者混用没有冲突。
