## 两套模型怎么对齐

OSI 是 ISO 的理论参考模型（七层），TCP/IP 是互联网的事实标准
（四层）。**背对照关系，讲问题时用五层说法**（物理链路合并不实用）：

| OSI 七层 | TCP/IP 四层 | 干什么 | 典型协议/设备 |
|---|---|---|---|
| 应用/表示/会话 | 应用层 | 为应用提供服务 | HTTP、DNS、SSH、SMTP |
| 传输 | 传输层 | 进程到进程的端到端 | TCP、UDP（**端口**区分进程） |
| 网络 | 网络层 | 主机到主机的路由寻址 | IP、ICMP（**路由器**） |
| 数据链路 | 网络接口层 | 相邻节点帧传输 | 以太网、ARP（**交换机**） |
| 物理 | 网络接口层 | 比特流传输 | 网线/光纤（**集线器/中继器**） |

## 数据怎么被装进网络

发送方**自上而下封装**，接收方**自下而上解封装**——每层给上层
数据加自己的头部（剥洋葱的逆过程）：


各层各管一个地址体系：应用层域名、传输层**端口**、网络层 **IP**、
链路层 **MAC**——ARP 协议负责"同网段内 IP → MAC"的翻译。

## 分层的意义与排障路径

分层 = **关注点分离**：HTTP 不关心走的是光纤还是 WiFi；IP 不关心
里面装的是 TCP 还是 UDP。换层不影响其他层，是整个互联网可演进的
根基（HTTP/3 把 TCP 换成 QUIC，应用层无感）。

排障也沿层走，**逐层二分**定位：

```bash
ping 10.0.0.2        # 网络层通不通（ICMP）
telnet 10.0.0.2 3306 # 传输层端口通不通（防火墙/监听）
curl http://api/health  # 应用层响应对不对
```

ping 通但端口不通 → 防火墙/服务没起；端口通但业务 5xx → 应用问题。
"能 ping 通却连不上"类问题的第一反应就是分层二分。

## 高频追问速答

- **交换机 vs 路由器**：二层按 MAC 转发（同网段），三层按 IP 路由
  （跨网段）。
- **为什么有了 TCP/IP 还背 OSI**：OSI 是"教学语言"——说"四层负载
  均衡（L4，按 IP+端口转发）还是七层负载均衡（L7，按 URL/HTTP 头
  转发）"用的是 OSI 编号（Nginx L7、LVS L4）。
- **ARP 欺骗**发生在链路层，**DNS 劫持**发生在应用层——知道层次才
  知道防御位置。

## 小结

- OSI 理论七层、TCP/IP 事实四层、口语五层；每层一个地址体系
  （域名/端口/IP/MAC），设备各守一层。
- 发送封装、接收解封装；分层换来演进自由与排障路径：ping → telnet
  → curl 逐层二分。
- L4/L7 负载均衡、ARP、ICMP 这些术语都要能落回"哪一层、谁负责"。
