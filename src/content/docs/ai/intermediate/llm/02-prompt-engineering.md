## 什么是提示工程

提示工程（Prompt Engineering）= **精心设计输入，引导模型输出想要的结果**。
它不改动模型任何权重，纯粹靠"问法"来调模型行为——成本低、见效快，是所有
AI Agent 开发的基本功。

## 从零样本到少样本

| 方式 | 做法 | 适用 |
|---|---|---|
| 零样本（Zero-shot） | 只给指令，不给示例 | 简单任务 |
| 少样本（Few-shot） | 指令 + 几个输入输出示例 | 格式敏感/易出错任务 |

示例越具体，模型越不容易跑偏，但也会吃掉宝贵的上下文窗口——这是提示词长度
与效果之间的持续权衡。

## 思维链（Chain-of-Thought, CoT）

让模型"把推理步骤写出来"，而不是直接给答案：

```text
❌ 直接问：23 × 17 = ?
✅ 加一句：请一步一步推理，写出计算过程后再给结果。
```

**CoT 显著提升多步推理/数学问题的正确率**，而且这纯粹是"让模型边想边说"——
模型在生成中间步骤时，相当于给自己更多算力展开推理。Agent 里的规划、
任务拆解，思想同源。

## 结构化提示

稳定复用的提示词通常拆成明确区块：

```text
角色：你是一位资深后端工程师
任务：审查下面的代码
约束：只找 bug，不讨论风格；每个问题给出行号和修复建议
输出格式：Markdown 列表
```

结构化提示词 = **角色 + 任务 + 约束 + 输出格式**，越清晰越可复现。这也是
「系统提示组装」笔记的源头：生产 Agent 会把这段提示按目录/索引动态拼装。

## 常见技巧

- **角色扮演**：给模型一个专业身份，激活对应知识分布。
- **明确输出格式**：JSON、Markdown、指定结构，减少解析成本。
- **负面约束+正面示例**：既说"不要什么"，也给"要什么"的样例。
- **迭代调试**：提示词要像代码一样反复测、持续优化。

## 小结

- 提示工程是不改权重的"行为引导"，是 Agent 开发的基本功。
- 少样本 + CoT + 结构化提示是三大提效手段。
- 提示词要当代码维护：约束清晰、可复现、持续迭代。
