调 LLM 接口时的 `temperature`、`top_p` 到底在调什么？答案一句话：
**模型每步输出的是"下一个 token 的概率分布"，推理参数决定你从这个分布里
怎么挑**。理解这一层，参数不再是玄学，而是对分布做手术的旋钮。

## 解码：从概率分布到具体 token

模型每一步给出词表上每个 token 的概率（softmax 后总和为 1）：

```mermaid

    D["原始分布<br/>（含大量低概率长尾）"] --> T["temperature<br/>锐化或平滑分布"]
    T --> K["top_k / top_p<br/>截断长尾候选"]
    K --> S["按概率采样（或贪心取最大）"]
    S --> O["本步输出 token"]

    class K hl
    classDef hl stroke-width:1.5px
```

- **贪心解码**（temperature=0 的近似）：永远取概率最大的 token——稳定、
  可复现倾向，但容易翻来覆去说车轱辘话。
- **采样解码**：按概率随机挑——多样性来自随机性，`temperature` 和
  `top_p` 都是给"随机"划定合理边界。

## temperature：锐化还是平滑

temperature 对原始 logits（softmax 前）做缩放：**T<1 锐化（分布更尖，
高概率词更垄断），T>1 平滑（长尾词更可能出现）**。

| 温度 | 分布形态 | 适用 |
| --- | --- | --- |
| 0~0.3 | 尖锐，近似贪心 | 抽取、分类、结构化输出、代码 |
| 0.5~0.7 | 适中 | 通用对话、摘要 |
| 0.8~1.2 | 平缓，多样 | 创意写作、头脑风暴 |

生产默认建议低温：**线上系统的第一诉求是稳定可预期，不是文采**。

## top_k 与 top_p：截断长尾

温度之外的第二道闸——**候选集裁剪**：

- **top_k**：只保留概率前 k 个 token 再采样（k=50 常见）。缺点是 k 固定，
  分布尖锐时 50 个太多、平缓时 50 个不够。
- **top_p（核采样）**：按概率从高到低累加，**累加到 p（如 0.9）为止**的
  动态候选集——分布尖时候选少、分布平时候选多，自适应。
- 两者可叠加（先 top_k 粗筛再 top_p 精筛）；多数 API 默认 `top_p=1`
  （不截断），此时温度是唯一的分布手术刀。

## 输出控制的其他旋钮

- **重复惩罚（repetition penalty / frequency penalty）**：给已出现 token
  降概率，治车轱辘话——调过头会伤害专有名词（术语被误伤说不全）。
- **max_tokens / stop 序列**：硬性输出边界，防跑飞必配。
- **种子（seed）**：部分 API 支持，固定种子 + 固定参数 ≈ 可复现（评测时有用，
  见评测与对齐篇）。

## 高频追问速答

- **temperature=0 输出完全确定吗？** 近似贪心但不保证——浮点并行运算的
  非确定性、批处理调度差异都可能引起微小抖动；要严格可复现用 seed +
  固定参数，并接受"近似确定"的现实。
- **temperature 和 top_p 一起调要注意什么？** 两者都在改"候选多宽"，
  **同时大幅调整会互相打架**——生产惯例是固定一个（常把 top_p 固定 1），
  只调温度。
- **为什么我的 RAG 回答时好时坏？** 先查检索稳定性，再看是不是高温采样
  把确定性需求变成了抽签——抽取类任务温度调低立竿见影（对照落地选型篇）。

## 小结

- 解码 = 对"下一 token 概率分布"做手术：temperature 改分布形状，
  top_k/top_p 裁候选集，采样或贪心做最终选择。
- 速查：抽取/结构化/代码 → 低温；对话 → 中温；创意 → 高温；生产默认低温。
- 调参先想清要"稳定"还是"多样"，两个旋钮别同时猛调。
