"让 AI 像人一样操作电脑"——打开软件、点按钮、填表单——是 Agent 的
终极形态之一（Computer Use）。技术核心出奇地简单：**截图给多模态
LLM，它输出"在哪做什么"，程序代为执行，再截图看结果**——Agent Loop
（第一篇）的视觉版。

## 循环：截图 → 理解 → 操作 → 再截图

```mermaid

    S["截屏（当前界面）"] --> M["多模态 LLM<br/>理解界面 + 决定下一步"]
    M --> A["输出结构化动作<br/>click(x,y) / type(text) / scroll"]
    A --> E["执行层代为操作"]
    E --> S2["再截屏验证结果"]
    S2 --> M
    class M hl
    class A hl
    classDef hl stroke-width:1.5px
```

- 与工具调用篇的循环同构，只是"工具"变成了**屏幕操作原语**（点击/
  输入/滚动/快捷键），"观察"变成了截图；
- 动作输出走**结构化输出**（JSON schema：action + 坐标 + 参数）——
  结构化输出篇的受限解码在这里是刚需（坐标格式错就点不中）。

## 与传统 RPA 的对比：泛化换精度

| | 传统 RPA（选择器/坐标脚本） | 视觉 Agent |
| --- | --- | --- |
| 定位方式 | CSS/选择器/固定坐标 | 看截图理解界面 |
| 界面变更 | 选择器失效即崩 | **泛化强**（认得"登录按钮"长什么样） |
| 精度与速度 | 高且快 | 坐标可能偏、每步一次多模态调用慢且贵 |
| 适用 | 流程固定的核心业务 | 长尾界面、跨应用、界面多变的场景 |

- 视觉 Agent 的价值在**泛化**：没写过的界面也能操作——代价是准确性
  与成本，两者是当前的主要瓶颈。

## 三个工程难点

1. **坐标精度**：LLM 给的点击坐标有偏差——解法：界面元素标注
   （截图上叠加编号框让模型选编号，而非裸坐标）、多次定位取交集；
2. **状态理解**：页面加载中/弹窗遮挡——需要"等待与重试"策略，不能
   盲目按计划走（对照错误恢复篇）；
3. **成本**：每步一次多模态调用（视觉 token 贵，多模态篇），复杂任务
   几十步就是几十次调用——**步数上限 + 缓存界面理解结果**。

## 安全：护栏篇的全部适用且更严格

视觉 Agent 操作的是**真实系统的真实界面**——护栏篇的每一层都必须
在场且加强：

- **最小权限**：限定可操作的软件与界面白名单；
- **关键操作人工确认**：删除、支付、发送——截图确认后再执行；
- **全量审计**：每步截图 + 动作留痕，可回放；
- **沙箱隔离**：优先在虚拟机/独立账号环境跑（Worktree 隔离篇的
  同型思想：把爆炸半径圈住）。

## 高频追问速答

- **为什么不直接操作 DOM/API？** DOM/API 路径精确快速但**只适用于
  自己能控制的软件**；视觉方式跨应用、跨平台泛化——两者按场景组合：
  能走 API 走 API，不能才视觉。
- **准确性怎么评估？** 建任务级评测集（目标+步骤+成功标准），看任务
  完成率与步数——应用评估篇的方法直接复用。
- **这东西现在能上生产吗？** 高风险操作慎用；"辅助人"（建议+人确认）
  是当前稳妥形态，"替代人"需要精度与安全再进一步。

## 小结

- 视觉 Agent = 多模态 LLM + 截图循环 + 结构化动作——Agent Loop 的
  视觉版，泛化强但精度与成本是瓶颈。
- 与传统 RPA 是"泛化换精度"的权衡，按界面稳定性组合使用。
- 操作真实系统 → 护栏篇全部适用且加强：白名单、确认、审计、沙箱。
