## 先想清楚：为什么读源码要会这个

HashMap 的 `hash & (n-1)`、线程池的 `ctl` 打包 workerCount 与
state、AQS 的 `waitStatus` 位标志——JDK 源码里位运算无处不在。
而看懂位运算的前提，是搞清**负数在二进制里怎么表示**。先用一个
"懵逼现场" motivate 一下：

```java
System.out.println(2 << 1);   // 4
System.out.println(-2 << 1);  // -4
System.out.println(-2 >> 1);  // -1
System.out.println(-2 >>> 1); // 2147483647  ← 为什么？？
```

## 原码、反码、补码：一场"让符号位参与运算"的演化

计算机只想做加法（减法 = 加负数，乘法 = 累加，除法 = 累减），
于是问题变成：**负数怎么存，才能让加法器无脑工作**。

### 原码：最直观但有俩坑

最高位当符号位（0 正 1 负），其余位表数值：

| 十进制 | 原码（8 bit） |
|---|---|
| 2 | 0000 0010 |
| -2 | 1000 0010 |

坑：①加法前得先判断符号，运算器复杂；②存在 `1000 0000`（-0）
和 `0000 0000`（+0）两个零，范围 -127~+127。

### 反码：符号位参与运算，但结果差 1

负数的反码 = 原码符号位不变、其余位取反。试着算 5-3：

```text
5 + (-3) = 0000 0101(反码) + 1111 1100(反码)
         = 0000 0001(反码) = 1     ← 应该是 2，差 1！
```

病因：-0 占了一个坑。反码运算循环进位时，符号位参与运算是对的，
但 0 有两种表示导致结果系统性偏差。

### 补码：反码 +1，问题终结

负数的补码 = 反码 + 1。再算 5-3：

```text
5 + (-3) = 0000 0101(补码) + 1111 1101(补码)
         = 0000 0010(补码) = 2     ✓
1 + (-1) = 0000 0001 + 1111 1111 = 0000 0000 = 0   ✓
```

- 零唯一（原 `-0` 的位置 `1000 0000` 让给了 -128，范围变为
  -128~+127，白赚一个数）；
- 符号位直接参与加法，无需特判；
- 减法统一为加法，硬件只需加法器。

**这就是现代计算机一律用补码存整数的原因。** 换算口诀：
正数三码相同；负数补码 = 反码 + 1，反码 = 补码 - 1。

## 移位运算：三个符号一种心法

| 运算符 | 规则 | 快捷理解 |
|---|---|---|
| `<<` 左移 | 高位丢弃，低位补 0 | `m << n = m × 2ⁿ` |
| `>>` 右移 | 低位丢弃，**高位补符号位** | `m >> n = m ÷ 2ⁿ`（向负无穷取整） |
| `>>>` 无符号右移 | 低位丢弃，**高位补 0** | 负数变正的大数 |

### 负数位移推导：以 -2 >> 1 = -1 为例

-2 的机器表示（int，32 位补码）：
`11111111 11111111 11111111 11111110`

右移 1 位，高位补符号位 1：
`11111111 11111111 11111111 11111111`

这是补码，倒推原码：减 1 得反码，符号位不变取反得
`10000000 00000000 00000000 00000001` = **-1** ✓

### 无符号右移：-2 >>> 1 = 2147483647

右移 1 位，高位**补 0**：
`01111111 11111111 11111111 11111111`

符号位变 0，成了正数，三码相同，直接读 = 2³¹-1 =
**2147483647** ✓ —— 无符号右移的本质是把补码当"纯比特串"挪动，
负号信息被移没了。

## 源码里的高频用法

```java
// ① HashMap：用位与代替取模（n 是 2 的幂时等价，且快得多）
index = hash & (n - 1);          // hash % n 的位运算版

// ② 容量扩容：判断/翻倍
if ((c & (c - 1)) == 0) {}       // 判断 2 的幂
newCap = oldCap << 1;            // ×2

// ③ 位标志打包：一个 int 存多个状态（线程池 ctl 就这么干）
int state = RUNNING | SHUTDOWN;  // 置位
boolean ok = (state & RUNNING) != 0;  // 测位
state &= ~STOP;                  // 清位
```

## 小结

- 补码胜出三件事：零唯一、符号位免特判、减法变加法；负数范围
  多出一个 -2ⁿ⁻¹。
- 移位心法：`<<` 乘 2ⁿ，`>>` 补符号位（负数永远 -1 兜底），
  `>>>` 补 0（负数瞬间变正大数）。
- 看到源码里的 `& (n-1)`、`ctl` 位打包，先想"2 的幂取模"与
  "位标志"，别被吓退。
